# Requirements — Local research runtime

Scope fence: [out-of-scope.md](out-of-scope.md). Design and decisions: [design.md](design.md). Testable form: [acceptance-criteria.md](acceptance-criteria.md).

Requirements are numbered `FR-R*` / `NFR-R*` — independently of the `FR-C*` / `FR-W*` numbering of the [tracker-connector](../tracker-connector/requirements.md) record, which stays valid as written except where a row below says otherwise.

## Functional

- **FR-R1 (Three independent modes, one switch)** — `research.mode` takes exactly one of three values, and each is a complete, independent way to run the connector: **`off`** (the default) — no research at all, the connector behaves exactly as phases 03–06 built it; **`worc`** — the report is produced by a worc task running the shipped triage flow (tracker-connector phase 07); **`local`** — the report is produced by an agent the connector launches itself (this record). Turning one on turns the others off; switching is one line and needs no other edit; no combination of keys can select two producers or none-with-research-expected. `worc` and `local` satisfy one `ResearchProvider` protocol declared in `core/`, and everything downstream of the report — the verdict block, the builder, the four verdicts' write-backs — is shared code that cannot tell them apart. With `off`, neither provider is constructed and every line of both paths is unreachable.
- **FR-R1a (Each mode's keys stand alone)** — a key that belongs to another mode is ignored rather than half-applied (`agents` under `mode: worc`, `flow` under `mode: local`); a key the selected mode **requires** and cannot default is a fail-closed refusal naming it. `mode: off` reads nothing else in the block, so a stale local configuration can sit there switched off and cost nothing.
- **FR-R2 (The connector may launch an agent)** — with `research.mode: local` the connector resolves an agent CLI with `shutil.which` and launches it as an argument list. This removes the "No agent runtime" invariant; the rules and the documents that state it are rewritten in the same change (see [D1](design.md#d1--the-connector-gets-an-agent-runtime-deliberately)). No model SDK is added: the runtime is `subprocess` plus `git`, and the connector's runtime dependency set does not grow.
- **FR-R3 (Research runs in a worktree of a clone the connector owns)** — the connector keeps its own clone under its home (`.worc-connect/repo.git`), fetches it before each research, and creates a detached worktree per research under `.worc-connect/worktrees/<task_id>`, based on `research.base_ref` — by default the clone's own default branch (`origin/HEAD`), so no configuration and no API call are needed to research a repository whose default branch is not `main`. worc's clone is never touched: no `git` process runs in it, and the invariant "the connector runs no `git` in the clone" survives unchanged. The worktree is removed when the research ends; orphans are pruned at startup.
- **FR-R4 (Nothing blocks)** — research runs in a **detached child process**, one per item; the polling tick starts children, polls for their results and returns. Neither the connector's loop nor worc's queue waits on a research: until a report exists, worc has been handed nothing at all. A connector restart re-adopts running children from their files rather than orphaning or duplicating them.
- **FR-R5 (Untrusted text never becomes an argument)** — the item's body reaches the agent only as a file (`RESEARCH_TASK.md`, written into the worktree). Every agent argv is a constant from configuration plus the connector's own fixed instruction sentence. This tracker-connector invariant is not relaxed by this record; it is the reason the prompt is a file.
- **FR-R6 (Two agents, ordered, with fallback)** — `research.agents` is an ordered list; the connector supports the shipped profiles `claude` and `codex` by name and a full argv form for anything else. A shipped profile is a pinned constant — launcher, fixed instruction sentence, output flag and the CLI's non-interactive / auto-approval flag — never derived from the installed CLI's help text; `doctor` prints each one in full, resolved path and version included, so the operator can see what the agent is being allowed to do (D6a). The next agent runs only when the previous one **fails** — the launcher does not resolve, a non-zero exit, no report, or an unparsable report. A report that parses is an answer, not a failure: `needs-info`, `duplicate` and `declined` end the chain exactly as `actionable` does. Each attempt gets a fresh worktree; the attempts and the agent that produced the report are recorded in the outcome and named in the task's provenance line.
- **FR-R7 (Timeouts are opt-in)** — `research.timeout_seconds: 0`, or the key omitted, means **no timeout**: the agent runs to completion however long it takes. A positive value terminates the attempt (terminate, then kill) and counts as a failure for FR-R6. Because the default cannot bound a run by the clock, the operator bounds it by hand, and that path is a first-class command rather than an afterthought: `worc-connect status` lists every running research with its agent, item, elapsed time and the PIDs of both the child and the agent, and `worc-connect research cancel` — by `task_id`, by item, or `--all` — ends the child **and** the agent it launched, including an agent orphaned by a dead child (D15).
- **FR-R8 (Concurrency cap)** — `research.max_concurrent` caps how many research children exist at once across all items; a tick that is at the cap starts none and tries again next tick. Exactly one research runs per `task_id`, enforced by the state row and an exclusive lock file.
- **FR-R9 (A visible state)** — a new connector state `researching` maps to the GitHub label `worc:researching`, applied when the child starts and replaced by the next state when the report is dispatched. One state label at a time, as before.
- **FR-R10 (The report contract is phase 07's, unchanged)** — `report.md` with the same machine-readable verdict block (`verdict`, `reason`, optional `duplicate_of`, optional draft acceptance criteria, optional `failing_test`), read by shared code, at `.worc-connect/research/<task_id>/report.md`. The deterministic builder decides what of it reaches the task; model output never becomes a queued task on its own. This survives from tracker-connector unchanged and is the reason phase 07 is a dependency.
- **FR-R10a (One quoted paragraph on the item)** — the report's `reason` field, and only that field, is quoted in the connector's comment on every verdict: capped in length, rendered as a blockquote, and neutralised so `@mention` and `#123` in agent text cannot ping people or link issues. No other part of the report is published; the file stays in the connector's home (D13). This applies to **both** producers — they share one comment builder — and resolves FU-1 in [follow-ups.md](../follow-ups.md).
- **FR-R10b (A research is not interrupted by the item moving)** — an edit, a new comment or a re-applied label while a research runs neither cancels nor restarts it; the run records the item's `updated_at` at start, and when it has advanced by dispatch time the task body and the comment say the item was edited after the research began. Re-trigger rules are unchanged (D14).
- **FR-R11 (Failure policy)** — `research.on_failure`: `proceed` (default) queues the implementation task from the raw item and says in the comment that research was skipped and why; `fail` creates no task and labels the item `worc:failed` with the reason. Either way the failure is visible on the item and the connector stays up.
- **FR-R11a (Retention is configured, and capped)** — `research.retain` (`on_failure` default, `always`, `never`) decides what of a finished research's working files survives, and `research.retain_max_runs` prunes the oldest retained runs beyond N (0 = no cap) at startup and after each dispatch. A failed research under the default keeps its `agent.log`, which is the operator's only diagnosis; no setting lets the connector's home grow without bound (D16).
- **FR-R12 (Preconditions are checked, and refused early)** — `worc-connect doctor` reports, and `watch` refuses to start with `research.mode: local` when: `git` does not resolve, no configured agent launcher resolves, the connector's clone cannot be created or fetched, or the connector home is not writable. A misconfigured research path never silently degrades into "queue it raw".
- **FR-R13 (The research clone cannot publish)** — the connector's clone is created with its push URL disabled and the agent is told, in the prompt template, that the research is read-only. The worktree is disposable and never becomes a branch, a commit or a pull request; only the report leaves it.

## Non-functional

- **NFR-R1 (Cross-platform, and the kill path first)** — Windows, Linux and macOS carry equal weight for every part of this runtime: detached children and process groups via the platform's own mechanism (`start_new_session` / creation flags), termination and escalation **without signals**, liveness by PID plus start time, `shutil.which` for `git` and every agent launcher (so `.exe` / `.cmd` resolve), `pathlib` + `Path.as_posix()` for stored and compared paths, atomic writes for `outcome.json`. The spawn / liveness / terminate seam is one module and both platform branches are exercised by injecting the platform, never by the host the suite happens to run on. A feature that works only on POSIX is not done.
- **NFR-R2 (Restart safety)** — every piece of a research's state is a file under `.worc-connect/research/<task_id>/`; killing and restarting the connector loses nothing and duplicates nothing.
- **NFR-R3 (Cost)** — one research per item per trigger (a re-trigger allocates the next sequence, as today). The polling tick itself still makes no model call; the model call is a child process the tick starts.
- **NFR-R4 (Small modules)** — the runtime lands as a leaf package `worc_connect/research/`, each module inside the repository's line budget, with an `import-linter` contract forbidding `core` from importing it. The composition root resolves the provider.
- **NFR-R5 (No new dependency)** — `deptry` sees nothing new: the runtime is the standard library plus executables the operator already has.

## Constraints inherited unchanged

- The gate is still the perimeter and still fails closed; research happens **after** the gate, never before it.
- The connector still reaches worc only through `tasks/preparing/` + `worc promote` and `worc list --format json`.
- The connector still holds, stores, logs and forwards no credentials, and forwards no extra environment to any child.
- Deterministic code still decides: the builder, not the agent, produces the task.
