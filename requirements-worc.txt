# worc itself, as a test dependency of this repository.
#
# One suite feeds a task file the builder generated to worc's *real* validation gate, because the
# connector has to produce a file worc accepts unchanged and worc rejects rather than repairs — a
# second, local copy of its rules could drift from the real ones without anything failing.
#
# It is not in `pyproject.toml`, and that is deliberate: worc is published to no package index (the
# name `worc` on PyPI is an unrelated project), so it can only be named by URL, and a direct
# reference inside the project's metadata is refused both by hatchling's default settings and by
# every package index this connector might later be published to. Nothing under `src/` imports it,
# so it is not a dependency of the product in any sense — only of one test.
#
#     pip install -r requirements-worc.txt
#
# Without it, `tests/test_worc_gate.py` skips and the rest of the suite is unaffected.
#
# Pinned to a release tag, not to a branch. worc tags its releases on its `release` branch, so a
# build from `dev` reports the last version reachable from `dev` (`0.10.3a2.devN`) even when it
# carries the whole contract — and the connector's version handshake, which reads `worc --version`,
# then refuses the contract it is being tested against. A tagged release reports its own number, so
# the suites that judge a generated task file and the shipped triage flow run against a worc whose
# version the connector also accepts; `tests/test_worc_gate.py` asserts the two agree. The tag must
# be at least `MINIMUM_VERSION` in `src/worc_connect/core/worc_version.py`.
